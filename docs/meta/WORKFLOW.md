# Development Workflow

## Before implementation

- Read the product brief, decision log, roadmap, and project rules.
- Preserve the paper as the source reference.
- Add or update an acceptance criterion before adding a new public behavior.

## During implementation

- Keep exact enumeration as the numerical reference path.
- Use deterministic seeds in tests.
- Expose diagnostics instead of silently hiding failed convergence.
- Keep experimental APIs separate from the stable high-level API.

## Before handoff

- Run the project verification script.
- Run unit and integration tests relevant to the changed stage.
- Document assumptions, limitations, and any reproduction gap.
- Do not claim PISA replication without specifying the data preparation and weighting path.
